## 已交付能力

1. `internal/runs/model.go`、`state.go`：纯 `Start` / `Advance` / `Finish` 转换及 typed domain error。终态与资源清理确认分离；Unknown 是零值，不能推断资源不存在。已 finalized Run 不允许改变状态，同终态收尾可幂等重试。
2. Finalization 矩阵覆盖 queued cancel、准备失败、Acquire 明确失败/不确定、execute 无记录/不确定、Agent/发布失败、取消、重启中断、成功 commit 和 Release 失败。已获取 Lease 时需要权威 Runtime disposition（或明确无 execution）及 Release 确认；publishing 拒绝取消。
3. `Store.CreateQueuedTx` 加入调用方 pgx 事务，不自行提交；`Read` 读取 Run。`ClaimNext` 使用固定全局 transaction advisory lock，随后检查非 queued 且未 finalized Run，再按 `created_at,id` 领取；V0 全局只执行一个 Run。
4. `BeginSandboxAcquire` 在外部调用前持久化 provider；`AttachSandboxRef` 补充不可变 ref，支持失败但未收尾 Run 的恢复。重复相同身份幂等，不同身份拒绝。provider/ref 保留审计信息，不向 JSON 暴露。
5. `AppendEvent` 锁 Run row 分配 durable sequence；同一 `(run_id,runtime_sequence)` 返回既有 Event，不重复分配。`ListEvents` 支持按 sequence 补读。payload 必须是合法 JSON 对象，匹配的产品 `run.*` 终态事件必须在 finalized 后才可写入。
6. `00002_run_event_sequences.sql` 新增序号计数器及 Runtime 序号 partial unique index；对已有事件按 max+1 初始化。`00001_initial.sql` 未修改。既有 migration 测试的版本数量断言从 1 更新为 2。

未增加依赖、通用 Save 抽象、外部队列或 E2B 实现。当前是底座模块，还没有接入会话 API、HTTP/SSE、scheduler、Coordinator 或真实 Claude 执行链路；这些属于后续任务。
