必须复用的约束：

- `SessionStore.prepare_run(run_id, cwd, source)` 在父进程 reserve/baseline 持久化后、worker 放行前调用。`list_ids()` 返回 set；`validate_candidate(run, candidate, source, baseline)` 验证归属。
- `ExecutionStore.reserve` 内部获取 `lifecycle_lock`。Finalize/delete 外层用同一锁；其他 Store 更新只用内部锁，避免递归获取 lifecycle lock。
- 新 process group 的 child 在 barrier 等待；父进程原子记录 PID/PGID 并 fsync 后才放行。parent 在此之前死亡，child 因 pipe EOF 自退，不能启动 SDK。
- candidate 创建及 durable 两次控制消息都需父进程落盘并 ACK。SDK Result 不是完成；SDK 关闭、Session fsync、durable ACK、Manifest 校验后才允许唯一成功终态。
- starting/running cancel 必须与 spawn 串行、终止并 wait 整个进程组，确认停止才转 awaiting_finalize；客户端断流不是 cancel，父进程继续 drain。
- 启动恢复清理完成后 health 才 ready；terminal 重复 execute 不重启 worker。
- commit 保留 source staging；abort 删除本 Run 新增 candidate/staging，但不删除 source/baseline 原件。未知 sidecar 布局与超过 200 字符的 encoded cwd 目前 fail closed，不擅自猜测布局/升级 SDK。
